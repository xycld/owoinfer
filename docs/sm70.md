# Volta (sm_70) support

`-DMOSSINFER_SM70=ON` adds Volta kernels, including Tesla V100, through the same object-library and runtime-dispatch
boundary as the Turing compatibility layer. The default build remains Ampere or newer. The option also carries the
existing Turing kernels: sm_70 SASS is forward-compatible within compute capability 7.x, and Turing still dispatches
to its own attention and native INT8 kernels.

## Build

Use CUDA **12.8 or 12.9** for the release preset, CMake 3.28 or newer, Ninja and GoogleTest. CUDA 13 removed Volta compilation and library support;
configuration rejects `MOSSINFER_SM70=ON` with that toolkit. A newer NVIDIA driver can run the CUDA 12 binary. On a
machine whose supported devices are all Volta, the probe recommends `cu12` even when the driver supports CUDA 13.

```sh
cmake --preset linux-cuda12-sm70 -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.9/bin/nvcc
cmake --build --preset linux-cuda12-sm70
CUDA_VISIBLE_DEVICES="" ctest --preset linux-cuda12-sm70 -L '^cpu$'
build-linux-cuda12-sm70/sm70_check all
build-linux-cuda12-sm70/sm70_check big
build-linux-cuda12-sm70/mossinfer_tests --gtest_filter='Sm70Build.*:GpuSm70.*:GpuSm75Convert.*'
cpack --config build-linux-cuda12-sm70/CPackConfig.cmake -B build-linux-cuda12-sm70
```

The package name ends in `-sm70`. The build/release matrix includes the Linux CUDA 12 SM70 preset. The CUDA architecture list of the ordinary core must stay sm_80 or newer; do not
set `CMAKE_CUDA_ARCHITECTURES=70` for the whole project. The option compiles the Volta kernel family separately and
adds sm_70 images to the portable SIMT kernels. `MOSSINFER_SM70=OFF` leaves the default kernel dispatch unchanged.

## Kernel paths

| Component | Volta path |
|---|---|
| bf16 linears | The existing compatibility layer's fp16 weights, row-scaled fp16 activations, cuBLASLt fp32 accumulation, and bias before the final bf16/fp32 rounding |
| INT8 ConvRot | Volta fp16 tensor cores with exact integer partial sums, then the existing quantization epilogues |
| INT4 ConvRot | The existing INT4-to-INT8 unpack route, followed by the Volta INT8 kernels |
| Exact attention | Dedicated fp16 WMMA kernel with fp32 online softmax and accumulation, bf16 input/output; non-causal head dimension 128 and causal 256, varlen and GQA |
| GatedDeltaNet | The chunked fp32 rule: Volta's 96 KiB shared memory fits it, so the smaller Turing recurrent fallback is unnecessary |
| VAE decode | The compatibility layer's fp32 convolution and attention; the planner retains reference decode precision |
| Elementwise kernels | The same portable SIMT sources, compiled for sm_70 as well |

Volta has no native INT8 tensor-core instruction. The quantized kernel keeps weights in their original one-byte
layout and converts tiles to fp16 in shared memory. Every signed byte is exact in fp16. Each fp32 partial sums at
most 1024 products, bounded by `1024 * 128 * 128 = 2^24`; it is converted exactly to int32 before the next partial.
The final integer sum rounds to fp32 once before dequantization. This avoids both a persistent expanded weight copy
and the precision loss of accumulating an arbitrarily long integer dot product in fp32. The existing plain,
gated-residual and SiTU-GLU epilogues keep their rounding order and column permutation.

Attention converts bf16 Q/K/V as it loads shared-memory tiles, leaves the inputs unchanged, and uses a bottom-right
causal mask. Fully masked query rows return zero and a positive-infinite log-sum-exp, matching the existing contract.
Its fp16 operand range and rounding limitations are the same as [the Turing layer](sm75.md#numerics).

The quality policy also follows Turing: an unset attention mode resolves to `exact` with an explicit reason. Explicit
8-bit attention and NVFP4 are refused. The fused bf16 block kernels, runtime LoRAs, control adapters, VAE encoding
(img2img, inpainting and references), and hires fix retain the existing sm_7x refusal/fallback policy. No sm_80 kernel
is launched as a substitute for a missing Volta implementation.

## Verification and performance

`sm70_check` reuses the compatibility layer's host-reference harness, compiled for sm_70. It exercises conversion,
fp16 GEMM, large activation rows and workspace chunks, INT8 GEMM, VAE convolution/attention, and both exact attention
head dimensions. `GpuSm70` also checks all three INT8 epilogues, row-stride padding, tail shapes, CUDA Graph replay,
and cancellation at K=131056 against a host int64 sum. Attention also checks log-sum-exp (including fully masked
rows) against the host reference.

`sm70_bench [rows] [sequence_length]` measures the four DiT GEMM shapes and both attention shapes with CUDA events
after warm-up. It is a development tool, not installed. Run the correctness tests before comparing its timings.

Measured on a Tesla V100-SXM2-32GB (80 SMs), CUDA 12.9.86, driver 580.196.07, GCC 14.2, Release, on 2026-11-01.
One GPU per measurement, default clocks, no concurrent workload on that GPU. CUDA-event means over 20 launches
following five warm-up launches, `sm70_bench 8222 4111`:

| Kernel | Shape | Time | Effective INT8 dot-product rate |
|---|---|---:|---:|
| QKV | M=8222, N=9216, K=3072 | 8.03 ms | 58.0 TOP/s |
| Projection + gated residual | M=8222, N=3072, K=3072 | 3.15 ms | 49.2 TOP/s |
| Up/gate + SiTU-GLU | M=8222, N=16384, K=3072 | 12.93 ms | 64.0 TOP/s |
| Down + gated residual | M=8222, N=3072, K=8192 | 6.15 ms | 67.3 TOP/s |
| DiT exact attention | B=2, L=4111, H=24, D=128 | 17.41 ms | — |
| Causal text attention | B=2, L=282, H=16, KV=4, D=256 | 0.259 ms | — |

The INT8 tile is 64x128x32, with 32x64 warps and the CUTLASS Volta shared-memory swizzle/register pipeline.
The main loop's shared storage is reused by the fused output stage. The SiTU factors use the same bf16 lookup-table
values as the Turing path. No global dequantization buffer or expanded resident weights are allocated. Attention
uses 128 query rows for D=128 and 64 for D=256, 32 keys per tile; a larger key tile was slower on this device.

End to end: MOSS-Image-SFT, Comfy-Org INT8 ConvRot DiT and Qwen3.5 9B W4A8 text encoder, `high`, exact attention,
Euler, CFG 3, seed 42, prompt `a red apple on a wooden table, natural light, detailed photograph`:

| Run | Measured result |
|---|---|
| 1024x1024, 20 steps, `max_speed`, embedding cache hit | 45.35 s total; 41.35 s denoise (~2.07 s/step), 3.29 s decode; 6.74 GiB device peak |
| 1024x1024, 3 steps, `max_speed`, embedding cache hit | 10.24 s total; 6.16 s denoise (~2.05 s/step), 3.28 s decode; 6.74 GiB device peak |
| 256x256, 3 steps, `min_memory`, uncached blue-teapot prompt | 2.91 s total; 1.17 s encode, 1.13 s denoise, 0.13 s decode; 1.04 GiB device peak; all 42 DiT blocks streamed |

The initial correctness implementation used a straightforward WMMA INT8 loop and took ~13.9 s/step at 1024x1024.
The optimized kernels reduce that by ~6.8x; the three-step PNGs before and after optimization are byte-identical.
This is a comparison within this Volta implementation, not a benchmark against another engine or an upstream V100
backend. The upstream build did not run on V100. The 20-step timing includes weight loading and decode but uses a
cached text embedding; the streamed run separately exercises cold text encoding.

Validation on V100: `sm70_check all` and `big`, all six `Sm70Build`/`GpuSm70`/`GpuSm75Convert` tests, Compute Sanitizer
memcheck (zero errors), and racecheck on attention and all INT8 epilogues including multiple accumulation segments
(zero errors/warnings). The default-off probe build passes its nine CPU tests. CTest reports no failures across 517 selected CPU cases
(with the normal missing-fixture skips), excluding the pre-existing `cli_check_verdict` CMake-script issue on CMake
3.31: that script drops empty list elements under unset CMP0007. Running it through a wrapper that sets CMP0007 to
NEW also passes. The shared-library `moss-server` and CLI also produce identical three-step 1024x1024 PNGs. The implementation was hardware-tested on V100; other devices were not available for regression.
